# Share and back up Studio templates

A `.sct-template` package is the portable version of a finished Studio design. It is different from a PDF/Word sample and from a generated certificate PDF.

## Export and import

1. Save the template. Export uses the saved version, not unsaved canvas changes.
2. Choose **Export** from the template actions and keep the package as a backup or share it with another club.
3. On the receiving computer, choose **Import Studio Template**, select the package and confirm its name/category.
4. Resolve font or mapping prompts, then preview representative entries and save.

## What the package includes

| Included | Not included |
| --- | --- |
| Page size, element positions, text and formatting | Loaded competition entries and results |
| Placeholder labels, mappings and combined text | Manual event corrections and print selection |
| Images, backgrounds and preprinted-paper flags | Generated or saved PDFs and print history |
| Visibility rules and layout boxes | App preferences and printer calibration |
| Font references; legacy embedded fonts where applicable | Ordinary system-font files in newly created templates |

Fixed text and images can still contain names or other personal information from the design sample. Inspect them before sharing. A package is a template backup, not a complete backup of the app.

## Fonts on another computer

New templates store the selected font family rather than distributing the system font file. If a font is installed on the receiving computer, the app uses it. If it is missing, import asks you to choose an available replacement. The bundled Liberation Sans is a portable option.

A replacement font, or a different version of the same font, can change line breaks and spacing. Check long text, combined fields and layout boxes after import. Older packages containing embedded fonts remain supported; this does not imply that new packages embed all selected fonts.

## Compatibility over time

Packages and template documents have format versions. Supported older formats are migrated when loaded by newer apps. If a package requires a newer unsupported format or feature, update the receiving app instead of editing version numbers or discarding fields.

Keep original exported packages as backups and verify them when moving to a new app version. Backward compatibility is maintained for supported historical formats; a future template is not guaranteed to open in an older app. See [current limitations](../reference/current-limitations.md).
